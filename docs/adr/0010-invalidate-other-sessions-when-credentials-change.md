# Invalidate other sessions when credentials change

Creating or changing a password and disconnecting Google revoke every refresh-token family for the User and increment a User auth version carried by access JWTs, immediately invalidating previously issued sessions before the initiating browser receives a fresh JobTrackr session. One password endpoint chooses creation or change from persisted User state: creation requires an atomically consumed Password Creation Grant, while change requires the current password, and changing to the current value is rejected. A successful Google reauthentication destroys its handshake session and creates a new five-minute session containing only the single-use grant. The schema backfills version `0`, legacy access tokens without the claim are interpreted as version `0`, and all newly issued tokens carry the claim; this avoids a deployment-wide logout while ensuring that any later credential change rejects both legacy and versioned tokens. Google linking only adds a password-reauthenticated sign-in method and therefore keeps existing sessions; the stricter invalidation for credential replacement or removal limits continued access through sessions established before the security change.
