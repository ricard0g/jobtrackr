# Model Sign-in Identities separately from Users

JobTrackr stores external Sign-in Identities in a dedicated table linked to Users instead of adding Google-specific identity columns to `users`. The provider is modeled explicitly but constrained to `GOOGLE` until another provider is deliberately implemented. Unique provider-subject and User-provider constraints preserve Google's stable identity mapping and the one-Google-identity-per-User rule; creation and linking are transactional so a concurrent loser reloads the winning link rather than creating a duplicate User, while an email collision without that subject is still refused. A just-in-time User starts without a display name and the UI falls back to Primary Email rather than importing Google profile data or deriving a name. Each Identity records immutable `linkedAt`, its latest verified provider email, and `lastUsedAt`, which advances after every successful Google callback that proves the identity, including sign-in, linking, and fresh reauthentication. If Google later returns a different verified email for a known subject, JobTrackr updates only the Identity's provider email and leaves the User's Primary Email unchanged. If the linked User is locked, disabled, or soft-deleted, sign-in fails generically: JobTrackr never creates a replacement User or moves the Identity. Disconnect hard-deletes the Identity Link, records a security event, and permits a later link only through the normal safeguards. Google tokens are not persisted because Google is used only as an identity provider.
