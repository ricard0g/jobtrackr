# Present Account Settings as a routed dialog

When Google is enabled, both password auth screens show the same policy-compliant “Continue with Google” link and explain that first use creates a JobTrackr User; it remains an ordinary navigation into Spring's redirect flow rather than loading Google's client-side identity SDK. The navbar's left account popover contains the User summary and Account Settings launcher, while the existing right-side icon remains the single logout action.
Within Account Settings, sign-in methods show concise password and Google lifecycle timestamps. Google disconnect stays visible but disabled when it is the only sign-in method, paired with the action to create a password; a changed provider email is displayed neutrally alongside the unchanged Primary Email. A dirty Profile form prompts before dialog closure or a full-page Google flow, and security actions never auto-save unrelated profile edits.
JobTrackr presents Account Settings as an accessible dialog at the canonical `/settings/account` path instead of as a standalone page or navbar popover. Contextual navigation uses React Router URL masking so the current protected screen remains mounted beneath the dialog, while direct visits and OAuth returns render the same dialog over a deterministic fallback. An unauthenticated direct visit goes through login and returns to Account Settings using an allowlisted internal path stored server-side for Google Sign-In, never an unchecked callback parameter. The Profile form edits only display name, trimming surrounding whitespace, converting blank to `null`, and enforcing 160 characters; Primary Email stays read-only and profile saves neither rotate nor revoke sessions. This preserves navigation context without duplicating settings routes across Kanban and Documents.
