# Cache DOCX previews in R2

When a user first previews a DOCX Base CV or Generated CV, the backend converts it to PDF and stores the result under a user-scoped preview prefix in R2; later previews reuse that PDF instead of repeating the conversion. Each immutable source owns one cached object at `users/{userId}/previews/base-cvs/{baseCvId}.pdf` or `users/{userId}/previews/generated-cvs/{generatedCvId}.pdf`. Original PDFs and Markdown do not create cached preview artifacts. R2 object existence is the cache registry; no preview record or state is stored in PostgreSQL. Concurrent cache misses for one source are coalesced within each backend instance, while rare duplicate conversions across instances are tolerated because they target the same deterministic key. Once conversion has started, the backend finishes and warms the cache even if the initiating dialog closes and aborts its response download. Deleting a source makes its preview unreachable immediately and schedules the preview object for deletion through the durable storage-cleanup queue, so temporary R2 failures do not block the user-facing deletion. All preview content is ownership-checked and streamed through the authenticated backend rather than exposed through signed R2 preview URLs. The source document remains canonical, while the cached PDF is a derived artifact that may be recreated, trading additional storage, backend bandwidth, and cleanup responsibilities for consistent authorization, faster repeat previews, and lower Gotenberg load.
